*** give-me a brief comparision between defun and cl-defun

**Brief comparison:*

| Feature | =defun= | =cl-defun= |
|---------|---------|------------|
| *Basic function definition* | ✓ | ✓ |
| *&rest parameters* | ✓ | ✓ |
| *&optional parameters* | ✓ | ✓ (with defaults) |
| *Keyword arguments (&key)* | ✗ | ✓ |
| *Destructuring parameters* | ✗ | ✓ |
| *Default values for optional* | ✗ | ✓ |
| *Library requirement* | Built-in | Requires =cl-lib= |

*Examples:*

#+begin_src elisp
;; defun - basic
(defun foo (a b &optional c &rest d) ...)

;; cl-defun - enhanced
(cl-defun foo (a b &optional (c 10) &key x y &rest d) ...)
#+end_src

*For your case:* Both should work identically with =&rest= parameters. The issue you're having is likely not related to =defun= vs =cl-defun= but rather the arity calculation logic.

*Recommendation:* Stick with =defun= since it's simpler and built-in, and your use case doesn't need the advanced features of =cl-defun=.
